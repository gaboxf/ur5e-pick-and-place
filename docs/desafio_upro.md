## Desafío 1 — Ta-Te-Ti robotizado

> **Modalidad:** Grupal — 2 o 3 integrantes · **Robot:** ABB IRB1100 · **Duración:** 3 semanas

### Presentación del desafío

¿Te animás a jugar al Ta-Te-Ti contra un robot industrial?

En este desafío deberán desarrollar un sistema que permita a una persona disputar una partida de **Ta-Te-Ti (Tres en Raya) contra el robot industrial ABB IRB1100**, utilizando un tablero físico compartido.

El jugador humano realizará sus movimientos dibujando sobre el tablero, mientras que el robot utilizará un fibrón para representar sus propias jugadas.

Para lograrlo, deberán integrar visión artificial, programación en Python y programación del robot industrial.

Una cámara deberá observar el tablero para identificar los movimientos realizados por el jugador. A partir de esa información, el sistema deberá interpretar el estado del juego, seleccionar una respuesta y ordenar al ABB que dibuje su jugada.

> **El desafío.** Desarrollar un sistema que permita jugar una partida completa de Ta-Te-Ti entre una persona y el ABB IRB1100, utilizando un mismo tablero físico. El sistema deberá reconocer las jugadas humanas mediante visión artificial, administrar las reglas del juego y ejecutar las respuestas del robot sobre el tablero.

### Objetivo

Desarrollar e integrar un sistema de visión artificial, una aplicación en Python y un robot industrial ABB IRB1100 para implementar un juego interactivo de Ta-Te-Ti sobre una superficie física compartida.

### Recursos disponibles

Para el desarrollo del desafío tendrán a disposición:

- Robot industrial ABB IRB1100.
- Fibrón instalado como herramienta del robot.
- Mesita de trabajo y superficie de escritura.
- Pizarrón u hojas de papel.
- Cámara para la adquisición de imágenes.
- Computadoras del laboratorio.
- Software y herramientas de programación disponibles para el robot.
- Bibliotecas y herramientas de desarrollo que consideren necesarias.

El equipo podrá seleccionar la superficie de juego que considere más adecuada, siempre que su disposición sea compatible con las condiciones de funcionamiento y seguridad de la celda.

### Requisitos funcionales obligatorios

#### Tablero físico

El juego deberá desarrollarse sobre un tablero físico de 3 × 3 casillas. El tablero deberá permitir que tanto la persona como el ABB representen sus jugadas sobre una misma superficie.

El equipo deberá garantizar que:

1. Las nueve casillas estén claramente definidas.
2. Los símbolos de ambos jugadores puedan distinguirse.
3. La cámara pueda observar el tablero.
4. Las posiciones físicas de las casillas se correspondan con su representación en el software.
5. El tablero permanezca estable durante el desarrollo de cada partida.

El tablero podrá encontrarse dibujado o preparado antes de comenzar. No será obligatorio que el robot dibuje las líneas divisorias.

#### Reconocimiento de jugadas mediante visión artificial

El sistema deberá utilizar una cámara para identificar las jugadas realizadas por el participante humano. Deberá ser capaz de:

1. Capturar imágenes del tablero físico.
2. Identificar sus nueve casillas.
3. Reconocer en qué casilla se realizó una nueva jugada.
4. Distinguir las casillas ocupadas de las disponibles.
5. Actualizar el estado del juego a partir de la información visual.
6. Evitar que una detección repetida de la misma marca se interprete como una nueva jugada.

Cuando una jugada no pueda identificarse de manera confiable, el sistema deberá informar la situación y evitar que el robot ejecute una respuesta basada en información incorrecta.

> **Herramientas de visión artificial.** Podrán utilizar OpenCV, YOLOv8 u otras bibliotecas o modelos que consideren adecuados. No será obligatorio entrenar una red neuronal. La selección de las herramientas y la estrategia de reconocimiento quedarán a criterio del equipo. La utilización de visión artificial para reconocer las jugadas humanas será obligatoria.

#### Lógica del juego

Desarrollar una aplicación en Python que administre una partida de Ta-Te-Ti. El sistema deberá:

1. Representar el estado actual del tablero.
2. Administrar los turnos de ambos participantes.
3. Reconocer las jugadas válidas del humano.
4. Impedir movimientos sobre casillas ocupadas.
5. Seleccionar automáticamente las jugadas del robot.
6. Identificar las condiciones de victoria.
7. Identificar las situaciones de empate.
8. Finalizar la partida cuando corresponda.
9. Permitir iniciar una nueva partida.

La estrategia utilizada por el robot será definida por el equipo. No será obligatorio desarrollar un adversario invencible, pero el sistema deberá realizar movimientos válidos y considerar las condiciones actuales del juego.

#### Ejecución de las jugadas mediante el ABB

El robot industrial deberá representar físicamente sus movimientos sobre el tablero compartido. El sistema deberá permitir que el ABB:

1. Identifique la casilla seleccionada por la aplicación.
2. Se desplace hasta la posición correspondiente.
3. Dibuje su símbolo dentro de la casilla.
4. Mantenga los trazos dentro de los límites previstos.
5. Evite alterar las marcas realizadas previamente.
6. Complete su movimiento y quede preparado para continuar la partida.

Las jugadas del robot deberán corresponderse con las decisiones generadas por el software. **No se aceptará una secuencia fija de movimientos que ignore el estado real del juego.**

#### Integración del sistema

La visión artificial, la lógica del juego y el ABB deberán funcionar de manera coordinada. El sistema deberá completar el siguiente ciclo de interacción:

1. El participante humano realiza una jugada sobre el tablero físico, con el robot detenido en condiciones seguras.
2. La cámara permite identificar el movimiento realizado.
3. La aplicación verifica la jugada y actualiza el tablero lógico.
4. El sistema determina si la partida continúa o ha finalizado.
5. Si corresponde, el robot selecciona su próxima jugada.
6. Una vez verificadas las condiciones de seguridad, el ABB representa físicamente su movimiento.
7. El sistema queda preparado para el siguiente turno.

Todo el proceso deberá funcionar de manera integrada, sin necesidad de modificar manualmente el código o las rutinas del robot entre jugadas. Podrán existir acciones de confirmación y habilitación necesarias para operar el sistema de manera segura.

> **Interacción física obligatoria.** No se aceptará como solución completa una aplicación en la que el jugador seleccione sus movimientos únicamente desde una interfaz de computadora. Las jugadas humanas deberán realizarse sobre el tablero físico y reconocerse mediante la cámara. La computadora podrá mostrar información del juego y proporcionar controles auxiliares, pero no reemplazar la interacción física.

#### Finalización de la partida

Al finalizar el juego, el sistema deberá:

- Reconocer si ganó el jugador humano.
- Reconocer si ganó el robot.
- Identificar una situación de empate.
- Informar el resultado.
- Evitar la ejecución de jugadas adicionales.
- Permitir preparar una nueva partida.

La limpieza o sustitución del tablero físico podrá realizarse manualmente, respetando las condiciones de seguridad correspondientes.

### Condiciones de funcionamiento

| Prueba | Resultado esperado |

El sistema deberá reconocer las jugadas humanas mediante una cámara, administrar correctamente el juego y permitir que el robot ejecute sus movimientos de manera física. La falta de integración entre cualquiera de estos componentes implicará el incumplimiento de los requisitos funcionales mínimos.

## Desafío 2 — Pick and Place guiado por visión artificial

> **Modalidad:** Grupal — 3 integrantes · **Robot:** Universal Robots UR5 · **Duración:** 3 semanas

### Presentación del desafío

¿Puede un robot industrial encontrar una pieza, recogerla y clasificarla sin conocer previamente su ubicación exacta?

En este desafío deberán desarrollar un sistema robotizado de clasificación de piezas mediante **visión artificial**, utilizando un robot industrial **UR5 equipado con un gripper de cuatro servomotores y puntas flexibles impresas en TPU**.

Las piezas estarán ubicadas sobre una superficie de trabajo conocida, pero sus posiciones podrán variar. El sistema deberá identificar cada pieza mediante una cámara, determinar su ubicación y utilizar esa información para que el robot pueda recogerla y depositarla en el lugar correspondiente a su categoría.

Para conseguirlo, deberán integrar procesamiento de imágenes, programación en Python, programación del robot industrial y control del gripper.

Una característica importante es que **ustedes mismos deberán seleccionar o diseñar las piezas que utilizarán**, considerando las características del sistema de visión y las posibilidades de manipulación del robot.

> **El desafío.** Desarrollar una celda robotizada capaz de identificar, localizar, recoger y clasificar piezas mediante visión artificial. El UR5 deberá recoger piezas ubicadas en diferentes posiciones dentro de una zona de trabajo delimitada, utilizando la información obtenida mediante una cámara y depositándolas en el destino correspondiente. El sistema deberá funcionar de manera integrada, sin necesidad de enseñar manualmente al robot la posición de cada pieza antes de recogerla.

### Objetivo

Desarrollar e integrar un sistema de visión artificial, una aplicación en Python y un robot industrial UR5 para localizar y clasificar piezas mediante operaciones de manipulación robotizada.

El proyecto deberá demostrar la capacidad de transformar información obtenida mediante una cámara en acciones físicas realizadas por un robot industrial.

### Recursos disponibles

Para el desarrollo del desafío tendrán a disposición:

- Robot industrial Universal Robots UR5.
- Gripper de cuatro servomotores con puntas flexibles impresas en TPU.
- Cámara para la adquisición de imágenes.
- Superficie de trabajo para colocar las piezas.
- Computadoras del laboratorio.
- Software y herramientas de programación disponibles para el UR5.
- Impresoras 3D para fabricar piezas y accesorios.
- Materiales y componentes electrónicos disponibles en el laboratorio.
- Bibliotecas, documentación y herramientas de desarrollo que consideren necesarias.

Podrán incorporar otros recursos, siempre que su utilización sea autorizada cuando corresponda.

### Requisitos funcionales obligatorios

#### Selección y diseño de piezas

El equipo deberá seleccionar, adaptar o diseñar las piezas que utilizará durante las operaciones de clasificación.

Se deberán utilizar **al menos dos categorías de piezas**, diferenciables mediante características que puedan identificarse utilizando visión artificial. Las piezas podrán distinguirse por su color, geometría u otras características observables.

El equipo deberá garantizar que:

1. Las piezas puedan identificarse mediante el sistema de visión seleccionado.
2. Sus características físicas sean compatibles con el gripper disponible.
3. Puedan recogerse y transportarse sin perder estabilidad durante los movimientos previstos.
4. Existan al menos dos categorías claramente diferenciadas.
5. Cada categoría tenga asignado un destino de clasificación.

Podrán utilizar piezas existentes o fabricar sus propios diseños mediante impresión 3D.

> **Libertad de diseño.** El equipo tendrá libertad para seleccionar los objetos, materiales, geometrías y criterios de clasificación. No se evaluará la complejidad estética de las piezas, sino que su diseño sea adecuado para el funcionamiento del sistema. La fabricación de piezas deberá contribuir a resolver el desafío, sin convertirse en el objetivo principal del proyecto.

#### Detección e identificación mediante visión artificial

El sistema deberá utilizar una cámara para identificar las piezas ubicadas sobre la superficie de trabajo. Deberá ser capaz de:

1. Capturar imágenes de la zona de trabajo.
2. Detectar la presencia de una pieza.
3. Identificar a qué categoría pertenece.
4. Determinar su ubicación dentro de la imagen.
5. Proporcionar la información necesaria para que el robot pueda realizar la operación correspondiente.

El equipo podrá utilizar OpenCV, YOLOv8 u otras técnicas de visión artificial que considere adecuadas. No será obligatorio entrenar una red neuronal si el problema puede resolverse mediante otras técnicas.

> **Identificación y localización obligatorias.** No será suficiente reconocer únicamente el tipo de pieza. El sistema también deberá determinar **dónde** se encuentra, ya que esta información será necesaria para que el robot pueda recogerla. La posición de recogida no podrá permanecer fija para todas las pruebas.

#### Localización en el espacio de trabajo

Las piezas podrán colocarse en diferentes posiciones dentro de una zona previamente delimitada. El sistema deberá establecer la correspondencia necesaria entre la información obtenida mediante la cámara y las posiciones utilizadas por el robot industrial. Deberá permitir:

1. Determinar la ubicación de una pieza sobre la superficie de trabajo.
2. Obtener una posición de recogida compatible con el sistema de coordenadas del UR5.
3. Adaptar la operación de recogida cuando la posición de la pieza cambie.
4. Respetar los límites de la zona de manipulación establecida.

Para este desafío se permitirá trabajar con las siguientes condiciones:

- Una superficie de trabajo plana y conocida.
- Una cámara fija durante el funcionamiento.
- Piezas de altura aproximadamente uniforme.
- Orientaciones de agarre previamente establecidas.
- Una única pieza por ciclo de clasificación.

No será obligatorio manipular piezas ubicadas a diferentes alturas ni resolver orientaciones arbitrarias en el espacio tridimensional. La estrategia de localización y transformación de coordenadas quedará a criterio del equipo.

#### Control del gripper

El UR5 dispone de un gripper compuesto por cuatro servomotores y puntas flexibles impresas en TPU. El equipo deberá desarrollar o integrar el mecanismo de control necesario para realizar las operaciones de agarre y liberación de las piezas.

El sistema deberá:

1. Permitir la apertura y cierre del gripper.
2. Adaptar la sujeción a las características de las piezas seleccionadas.
3. Coordinar el funcionamiento del gripper con los movimientos del robot.
4. Mantener las piezas sujetas durante su transporte.
5. Liberarlas correctamente en los destinos correspondientes.

El equipo tendrá libertad para definir la estrategia de control, los componentes auxiliares y los mecanismos de comunicación que considere necesarios, utilizando los recursos disponibles y autorizados.

#### Programación del UR5

El equipo deberá programar el robot industrial para ejecutar las operaciones de manipulación. El sistema deberá permitir que el UR5:

1. Se aproxime a una pieza detectada.
2. Alcance una posición adecuada para su recogida.
3. Accione el gripper para sujetarla.
4. Transporte la pieza hacia el destino correspondiente.
5. La deposite en la zona de clasificación asignada.
6. Finalice la operación y quede preparado para realizar un nuevo ciclo.

Los movimientos deberán respetar las limitaciones del robot, de la herramienta y del espacio de trabajo.

> **Programación del robot.** Aunque durante el curso se trabajó con el robot ABB, en este desafío deberán aplicar y ampliar esos conocimientos para programar un robot industrial diferente. Podrán utilizar la documentación del fabricante, herramientas de inteligencia artificial y otros recursos para aprender las características de programación del UR5.

#### Integración del sistema

La visión artificial, la aplicación Python, el controlador del UR5 y el gripper deberán funcionar como partes coordinadas de un mismo sistema.

El sistema deberá realizar una operación completa que incluya:

- Identificación de la pieza.
- Determinación de su ubicación.
- Selección del destino correspondiente.
- Ejecución de los movimientos del robot.
- Accionamiento del gripper.
- Depósito de la pieza.
- Finalización del ciclo.

La operación deberá realizarse sin que el usuario tenga que introducir manualmente las coordenadas de recogida ni modificar el programa entre ciclos. Se permitirá que un operador coloque las piezas y confirme el inicio de una operación, respetando las condiciones de seguridad.

> **Integración obligatoria.** No será suficiente presentar un programa Python que detecte piezas y, por separado, una rutina del UR5 que realice movimientos preprogramados. El robot deberá utilizar las posiciones y categorías obtenidas por el sistema de visión para realizar las operaciones de manipulación. La integración entre los diferentes componentes constituye uno de los objetivos fundamentales del desafío.

#### Control de operaciones y situaciones especiales

El sistema deberá proporcionar información que permita conocer el estado general de las operaciones. Como mínimo, deberá permitir identificar:

- Cuando el sistema está preparado para comenzar.
- Cuando se detecta una pieza válida.
- Cuando el robot está ejecutando una operación.
- Cuando finaliza un ciclo de clasificación.
- Cuando no se detecta una pieza o no existe información suficiente para comenzar una operación.

En caso de no detectar una pieza válida, el sistema no deberá iniciar una trayectoria de recogida basada en coordenadas inexistentes o no verificadas.

## Desafío 3 — Navegación autónoma mediante visión artificial

> **Modalidad:** Grupal — Máximo 2 integrantes · **Plataforma:** Robot móvil con Raspberry Pi, Arduino y cámara · **Duración:** 3 semanas

### Presentación del desafío

¿Es posible desarrollar un robot móvil capaz de seguir una trayectoria e interpretar señales de manera autónoma?

En este desafío deberán transformar un robot móvil en un vehículo autónomo capaz de desplazarse mediante **visión artificial**.

El robot deberá utilizar una cámara para identificar una línea negra sobre una superficie blanca y ajustar sus movimientos para seguirla. Además, durante el recorrido encontrará señales visuales que deberá reconocer e interpretar para modificar su comportamiento.

Por ejemplo, el robot podría encontrar una señal de detención, permanecer detenido durante unos segundos y luego continuar. En otro sector podría encontrar una señal que le indique reducir la velocidad.

Para conseguirlo, deberán integrar procesamiento de imágenes, programación en Python, control de motores y comunicación entre los componentes del robot.

> **El desafío.** Desarrollar un robot móvil capaz de seguir autónomamente una línea negra sobre una superficie blanca e interpretar señales visuales que modifiquen su comportamiento. El robot deberá tomar decisiones utilizando la información obtenida mediante su cámara, sin depender de un operador que controle manualmente sus movimientos durante el recorrido.

### Objetivo

Desarrollar e integrar un sistema de visión artificial y control para que un robot móvil pueda seguir una trayectoria marcada sobre una superficie e interpretar señales visuales durante su desplazamiento.

El proyecto deberá demostrar la capacidad de transformar información visual en decisiones y movimientos físicos coordinados.

### Recursos disponibles

Para el desarrollo del desafío tendrán a disposición:

- Kit de robot móvil ensamblado.
- Base móvil con motores y ruedas.
- Controlador de motores.
- Arduino.
- Raspberry Pi.
- Cámara compatible con Raspberry Pi.
- Sistema de alimentación del robot.
- Mesa de superficie blanca.
- Cinta aisladora negra para construir el recorrido.
- Computadoras del laboratorio.
- Materiales para imprimir las señales visuales.
- Bibliotecas, documentación y herramientas de desarrollo que consideren necesarias.

Podrán incorporar otros componentes disponibles en el laboratorio, siempre que su utilización sea autorizada cuando corresponda.

> **Proyecto de referencia.** Pueden consultar el proyecto educativo Duckietown, que utiliza robots móviles, cámaras y entornos con calles y señales para desarrollar aplicaciones de navegación autónoma. Sitio oficial: <https://duckietown.com/>. Este recurso es una referencia conceptual. No será obligatorio reproducir sus escenarios, arquitectura ni bibliotecas.

### Requisitos funcionales obligatorios

#### Trayectoria de navegación

El recorrido se construirá utilizando una única línea de cinta aisladora negra sobre una mesa de superficie blanca. No será necesario construir una maqueta, calles ni carriles delimitados por dos líneas.

La trayectoria deberá incluir:

1. Un tramo recto.
2. Al menos dos curvas que requieran correcciones de dirección.
3. Dos señales visuales diferentes distribuidas durante el recorrido.
4. Un punto de inicio y uno de finalización identificables.

La disposición del recorrido deberá permitir comprobar que el robot realiza correcciones de dirección utilizando la información de la cámara. La trayectoria deberá ubicarse dentro de una zona segura de la mesa, con suficiente espacio para el desplazamiento y las correcciones del robot.

#### Seguimiento de línea mediante visión artificial

El robot deberá utilizar su cámara para identificar y seguir la línea negra sobre el fondo blanco. El sistema deberá ser capaz de:

1. Capturar imágenes durante el desplazamiento.
2. Detectar la línea negra mediante procesamiento de imágenes.
3. Determinar la posición relativa de la línea respecto del robot.
4. Corregir la dirección del desplazamiento cuando sea necesario.
5. Recorrer tramos rectos y curvas sin intervención manual.
6. Adaptar continuamente el movimiento en función de la información visual.

Las correcciones deberán depender de las imágenes capturadas por la cámara.

> **Seguimiento visual obligatorio.** El robot deberá utilizar su cámara como fuente principal de información para seguir la línea negra. No se aceptará como solución completa un sistema que utilice exclusivamente sensores infrarrojos tradicionales ni una secuencia predeterminada de movimientos. Podrán utilizar sensores adicionales como complemento, pero no para reemplazar el seguimiento mediante visión artificial.

#### Reconocimiento de señales visuales

Durante el recorrido, el robot deberá reconocer **al menos dos señales diferentes**, que modificarán su comportamiento.

**Señal 1 — Detención (STOP).** Al reconocer esta señal, el robot deberá:

- Interrumpir su desplazamiento.
- Permanecer detenido durante al menos tres segundos.
- Reanudar el seguimiento de línea cuando corresponda.

**Señal 2 — Reducción de velocidad.** Al reconocer esta señal, el robot deberá:

- Reducir su velocidad de desplazamiento.
- Continuar siguiendo la línea negra a una velocidad inferior a la habitual.
- Recuperar la velocidad normal cuando finalice la condición definida por el equipo.

Las señales podrán ubicarse junto a la trayectoria, de manera que sean visibles para la cámara sin impedir el seguimiento de la línea. El equipo deberá garantizar que las señales no sean confundidas con la trayectoria y que puedan reconocerse durante el desplazamiento.

#### Identificación mediante marcadores visuales

Para reconocer las señales podrán utilizar marcadores **ArUco, AprilTags u otras técnicas de visión artificial**. Cada señal deberá estar asociada con una instrucción específica.

El sistema deberá:

1. Detectar las señales durante el recorrido.
2. Identificar la instrucción correspondiente.
3. Ejecutar la acción asociada.
4. Continuar el recorrido según corresponda.
5. Evitar que una misma señal provoque ejecuciones incorrectas o repetidas de la instrucción.

Por ejemplo, una señal STOP que permanece visible durante varios fotogramas no deberá provocar que el robot reinicie indefinidamente el tiempo de detención.

> **Herramientas de visión artificial.** Podrán utilizar OpenCV, ArUco, AprilTags u otras herramientas de visión artificial que consideren adecuadas. No será obligatorio utilizar YOLOv8 ni entrenar una red neuronal. La elección de las técnicas de procesamiento y reconocimiento quedará a criterio del equipo.

#### Control de movimiento

El robot deberá ajustar sus movimientos en función de las decisiones generadas por el sistema. Deberá ser capaz de:

1. Avanzar siguiendo la línea.
2. Corregir su dirección hacia ambos lados.
3. Modificar su velocidad.
4. Detenerse cuando corresponda.
5. Reanudar el movimiento después de una detención programada.
6. Mantener el seguimiento de línea mientras ejecuta las condiciones de velocidad establecidas.

El equipo deberá decidir cómo implementar el control de los motores y la coordinación entre los dispositivos disponibles. No se impondrá una técnica específica de control, siempre que el comportamiento obtenido permita cumplir los requisitos del desafío.

#### Integración del sistema

El procesamiento de imágenes, el reconocimiento de señales y el control de movimiento deberán funcionar como componentes coordinados de un mismo sistema.

Durante el recorrido, el robot deberá:

1. Identificar la línea negra.
2. Ajustar sus movimientos para seguirla.
3. Reconocer las señales visuales.
4. Interpretar las instrucciones correspondientes.
5. Modificar su comportamiento.
6. Continuar siguiendo la trayectoria.
7. Completar el recorrido establecido.

La implementación deberá funcionar sin necesidad de modificar manualmente el programa entre las diferentes secciones del circuito.

> **Integración obligatoria.** No será suficiente demostrar un seguidor de línea y, por separado, un programa capaz de reconocer marcadores visuales. El robot deberá seguir la trayectoria y responder a las señales durante un mismo recorrido autónomo. La integración entre percepción, interpretación de señales y control de movimiento es un requisito fundamental del desafío.

#### Gestión de situaciones especiales

El sistema deberá contemplar situaciones en las que la información visual no sea suficiente para continuar el recorrido. Como mínimo, deberá:

- Identificar cuándo la línea deja de detectarse de manera confiable.
- Evitar continuar avanzando indefinidamente sin una referencia válida.
- Detener el desplazamiento de forma controlada si la trayectoria permanece perdida.
- Permitir recuperar o reiniciar el funcionamiento bajo condiciones seguras.

También deberá evitar que una pérdida de comunicación entre los componentes provoque que los motores continúen ejecutando indefinidamente la última orden recibida. La estrategia para gestionar estas situaciones quedará a criterio del equipo.

### Condiciones de funcionamiento

Para considerar funcional el proyecto, el robot deberá completar un recorrido sobre la línea negra, respondiendo correctamente a las señales visuales. Durante la evaluación final se verificarán los siguientes aspectos:

| Prueba | Resultado esperado |
|---|---|
| Inicio del recorrido | El robot comienza a desplazarse desde el punto establecido. |
| Seguimiento en rectas | Mantiene el seguimiento de la línea negra. |
| Seguimiento en curvas | Corrige la dirección y continúa siguiendo la línea. |
| Señal STOP | Reconoce la señal y permanece detenido durante al menos tres segundos. |
| Reanudación | Continúa el recorrido después de la detención. |
| Reducción de velocidad | Reconoce la señal y disminuye su velocidad de desplazamiento. |
| Seguimiento a velocidad reducida | Continúa siguiendo la línea mientras mantiene la reducción de velocidad. |
| Recuperación de velocidad | Regresa a su velocidad normal cuando termina la condición establecida. |
| Detecciones repetidas | Evita ejecutar incorrectamente una misma instrucción varias veces. |
| Pérdida de línea | Detiene el movimiento de manera controlada cuando no puede continuar de forma confiable. |
| Integración | Completa el recorrido utilizando visión artificial y control autónomo. |

El docente podrá modificar razonablemente la disposición de algunas curvas o señales dentro de las condiciones previstas, para comprobar que el sistema utiliza la información visual y no depende de una secuencia fija de movimientos.

La demostración deberá realizarse sin que un operador controle manualmente la dirección o la velocidad durante el recorrido. Se permitirá la intervención del operador para iniciar, detener o recuperar el sistema en situaciones que lo requieran.

> **Condición obligatoria de aprobación.** Para aprobar será necesario demostrar que el robot puede seguir autónomamente una línea negra sobre fondo blanco y responder correctamente a las dos señales visuales obligatorias. El seguimiento de línea y el reconocimiento de señales deberán funcionar de manera integrada. Un robot que solamente siga una línea, o que únicamente reconozca señales sin modificar su comportamiento durante el recorrido, no cumplirá los requisitos mínimos del desafío.

### Funcionalidades adicionales

Una vez cumplidos los requisitos obligatorios, podrán incorporar funcionalidades que amplíen el proyecto.

> **Ampliaciones opcionales.**
>
> - **Navegación en intersecciones.** Incorporar bifurcaciones en la línea y señales que indiquen qué dirección debe tomar el robot.
> - **Reconocimiento de señales sin marcadores.** Desarrollar un sistema que interprete señales por su apariencia, sin utilizar marcadores ArUco o AprilTags.
> - **Control avanzado de trayectoria.** Incorporar y ajustar un controlador que permita mejorar la estabilidad, reducir las oscilaciones o mantener un seguimiento más preciso.
> - **Detección de obstáculos.** Incorporar mecanismos para identificar obstáculos sobre la trayectoria y detener el robot cuando sea necesario.
> - **Monitoreo del recorrido.** Desarrollar una aplicación que permita visualizar la cámara, el estado de navegación, las señales detectadas y las acciones ejecutadas.
>
> Las funcionalidades adicionales no reemplazan los requisitos obligatorios y su valoración estará sujeta a la rúbrica correspondiente.

### Seguridad y utilización del equipamiento

El robot móvil deberá utilizarse respetando las condiciones de seguridad establecidas para el laboratorio.

> **Seguridad durante las pruebas.**
>
> - La trayectoria deberá ubicarse lejos de los bordes de la mesa, dejando suficiente margen para los movimientos y posibles desviaciones.
> - Se deberán adoptar medidas físicas de protección para evitar que el robot caiga de la superficie durante las pruebas.
> - No se permitirá realizar pruebas que puedan producir daños al equipamiento o a las personas.
> - El sistema deberá contar con una forma accesible de detener el robot.
> - Se deberá comprobar que los motores y sus controladores reciban una alimentación adecuada.
> - Las conexiones entre Raspberry Pi, Arduino, controladores y sistemas de alimentación deberán verificarse antes de energizar el robot.
> - No se permitirá dejar el robot funcionando sin supervisión.
> - Ante comportamientos inesperados, deberá detenerse la operación y comprobarse su causa antes de continuar.
> - Toda prueba física deberá realizarse bajo las condiciones de supervisión establecidas por el docente.

## Desafío 4 — Inspector visual inteligente mediante YOLOv8-seg

> **Modalidad:** Individual · **Tecnologías principales:** Python, YOLOv8-seg y OpenCV · **Duración:** 3 semanas

### Presentación del desafío

¿Cómo podemos determinar si un objeto cumple determinadas condiciones utilizando visión artificial?

En este desafío deberán desarrollar un **sistema inteligente de inspección visual**, capaz de identificar objetos, aislarlos de su entorno y analizar sus características para tomar decisiones.

Para ello utilizarán **YOLOv8 con un modelo de segmentación de instancias preentrenado**, combinado con técnicas de procesamiento de imágenes mediante OpenCV.

A diferencia de la detección tradicional, que permite localizar objetos mediante rectángulos delimitadores, la segmentación proporciona máscaras que representan las regiones ocupadas por los objetos detectados. Estas máscaras permiten realizar análisis adicionales sobre las características visuales de cada objeto.

El desafío consiste en aprovechar esa información para construir un sistema capaz de verificar condiciones previamente establecidas y determinar si un objeto cumple o no con los criterios de inspección.

> **El desafío.** Desarrollar una aplicación que utilice YOLOv8-seg para identificar y segmentar objetos, analizar sus características mediante procesamiento de imágenes y clasificarlos según condiciones de inspección definidas por el estudiante. El sistema deberá integrar segmentación, extracción de características, toma de decisiones y presentación de resultados.

### Objetivo

Desarrollar una aplicación de inspección visual que combine un modelo preentrenado de segmentación de instancias con técnicas de procesamiento de imágenes, permitiendo analizar características de objetos y determinar si cumplen condiciones previamente definidas.

El proyecto deberá demostrar la capacidad de utilizar los resultados de un modelo de inteligencia artificial como parte de un sistema de análisis y toma de decisiones.

### Recursos disponibles

Para el desarrollo del desafío tendrán a disposición:

- Computadoras del laboratorio.
- Cámaras disponibles para capturar imágenes o videos.
- Python y las bibliotecas necesarias.
- Modelos preentrenados de YOLOv8-seg.
- OpenCV y NumPy.
- Objetos y elementos disponibles en el laboratorio.
- Recursos audiovisuales que puedan utilizarse legalmente.
- Documentación y herramientas de inteligencia artificial que consideren necesarias.

No será obligatorio utilizar una cámara en tiempo real. Se permitirá trabajar con imágenes o videos almacenados.

> **Documentación de referencia.**
>
> - Ultralytics — Segmentación de instancias: <https://docs.ultralytics.com/es/tasks/segment/>
> - Ultralytics — Categorías del dataset COCO: <https://docs.ultralytics.com/datasets/detect/coco/>
>
> Estas referencias permiten consultar las características de los modelos de segmentación y las categorías reconocidas por los modelos preentrenados.

### Selección del escenario de inspección

Cada estudiante deberá seleccionar un escenario de inspección visual y definir qué objetos analizará. Se podrán utilizar objetos cotidianos, elementos del laboratorio o imágenes y videos que contengan objetos reconocidos por el modelo preentrenado.

Algunas posibilidades son:

- **Inspección de envases.** Analizar botellas, tazas u otros recipientes, verificando características como color, orientación o forma visible.
- **Verificación de estaciones de trabajo.** Analizar elementos presentes sobre una mesa, como teclados, mouse, celulares o libros, verificando su disposición y determinadas características visuales.
- **Inspección geométrica.** Analizar objetos y comparar características como área segmentada, proporciones, contornos u orientación con valores de referencia.
- **Otros escenarios.** Se permitirá proponer aplicaciones diferentes, siempre que permitan utilizar segmentación y desarrollar un sistema de inspección que cumpla los requisitos obligatorios.

> **Selección de objetos.** Los objetos seleccionados deberán pertenecer a categorías que el modelo preentrenado pueda reconocer y segmentar adecuadamente. Antes de comenzar el desarrollo completo, deberán comprobar que los objetos elegidos producen resultados de segmentación útiles para el análisis propuesto. No será obligatorio utilizar frutas, fabricar piezas ni adquirir materiales especiales. La propuesta de inspección deberá ser aprobada por el docente.

### Requisitos funcionales obligatorios

#### Adquisición de imágenes

La aplicación deberá permitir obtener imágenes de los objetos que serán inspeccionados. Podrán utilizar alguna de las siguientes fuentes:

- Cámara en tiempo real.
- Imágenes almacenadas.
- Videos grabados previamente.

La fuente seleccionada deberá permitir demostrar diferentes situaciones de inspección. El estudiante deberá disponer de ejemplos suficientes para comprobar el comportamiento del sistema ante condiciones correctas e incorrectas. Cuando utilice imágenes o videos externos, deberá indicar su procedencia.

#### Segmentación mediante YOLOv8

El sistema deberá utilizar un modelo preentrenado de segmentación de instancias de YOLOv8. Deberá ser capaz de:

1. Procesar las imágenes obtenidas.
2. Identificar los objetos correspondientes al escenario seleccionado.
3. Obtener las máscaras de segmentación de los objetos detectados.
4. Asociar cada máscara con el objeto correspondiente.
5. Utilizar las máscaras como parte del proceso de inspección.

No será suficiente ejecutar el modelo y mostrar las máscaras sobre la imagen. El proyecto deberá utilizar la información proporcionada por la segmentación para realizar análisis adicionales.

> **Uso obligatorio de segmentación.** El análisis de las características visuales deberá utilizar las máscaras generadas por YOLOv8-seg. No se aceptará como solución completa una aplicación que solamente utilice los rectángulos de detección o las etiquetas de clase. La segmentación deberá cumplir una función concreta dentro del sistema de inspección.

#### Extracción y análisis de características

Una vez segmentados los objetos, la aplicación deberá analizar sus características mediante procesamiento de imágenes.

Se deberán implementar **al menos dos características medibles**, relacionadas con el escenario de inspección seleccionado. Algunos ejemplos son:

- Color predominante.
- Proporciones geométricas.
- Área visible del objeto.
- Relación entre ancho y alto.
- Orientación.
- Características del contorno.
- Presencia de determinadas regiones de color.
- Posición relativa dentro de una zona de inspección.

Las características seleccionadas deberán poder obtenerse y justificarse a partir de las imágenes disponibles. No será obligatorio medir dimensiones reales en milímetros. Si el estudiante decide hacerlo, deberá contar con una referencia de escala o calibración adecuada.

#### Definición de criterios de inspección

Cada estudiante deberá establecer las condiciones que utilizará para determinar si un objeto cumple los requisitos del escenario. Las condiciones deberán estar relacionadas con las características analizadas.

Por ejemplo, un sistema podría verificar que un objeto:

- Pertenezca a una categoría determinada.
- Presente un color esperado.
- Mantenga proporciones dentro de un rango definido.
- Se encuentre en una orientación admitida.
- Cumpla una combinación de características.

El estudiante deberá **definir y justificar los criterios utilizados**. No se aceptarán decisiones arbitrarias que no estén relacionadas con el análisis visual realizado.

> **Criterios de inspección.** No es obligatorio detectar defectos reales de fabricación. Se permitirá establecer condiciones de aceptación y rechazo adaptadas al escenario elegido. Por ejemplo, verificar una configuración visual, comparar características con una referencia o comprobar determinados parámetros. Lo importante es que las condiciones puedan medirse, evaluarse y comprobarse mediante pruebas.

#### Clasificación de los resultados

La aplicación deberá determinar el resultado de la inspección de cada objeto analizado. Como mínimo, deberá contemplar:

- **APROBADO.** El objeto cumple las condiciones de inspección establecidas.
- **RECHAZADO.** El objeto fue identificado y analizado, pero incumple al menos una condición.
- **NO EVALUABLE.** No fue posible realizar una inspección confiable, por ejemplo, porque el objeto no pudo detectarse o segmentarse adecuadamente.

El sistema deberá informar el resultado y proporcionar información que permita comprender la decisión tomada. En el caso de un rechazo, deberá identificar qué condición o condiciones no se cumplieron.

#### Visualización de resultados

La aplicación deberá mostrar de forma comprensible la información obtenida durante la inspección. Como mínimo, deberá permitir visualizar:

1. La imagen original o procesada.
2. Los objetos identificados.
3. Las regiones segmentadas.
4. Las características medidas.
5. El resultado final de la inspección.
6. Las condiciones incumplidas, cuando corresponda.

La forma de presentación quedará a criterio del estudiante. Podrá utilizar ventanas gráficas de OpenCV, una interfaz desarrollada en Python u otras herramientas que considere adecuadas. No será obligatorio desarrollar una interfaz gráfica compleja.

#### Registro de inspecciones

El sistema deberá registrar los resultados de las inspecciones realizadas. El registro deberá permitir conocer, como mínimo:

- Cantidad de objetos inspeccionados.
- Cantidad de objetos aprobados.

## Desafío 5 — Detector de objetos personalizado mediante YOLOv8

> **Modalidad:** Individual · **Tecnologías principales:** Python, YOLOv8 y OpenCV · **Duración:** 3 semanas

### Presentación del desafío

¿Es posible enseñarle a un sistema de inteligencia artificial a reconocer objetos que originalmente no sabe identificar?

Los modelos de detección de objetos, como YOLOv8, pueden reconocer diferentes categorías de elementos presentes en imágenes y videos. Sin embargo, los modelos preentrenados solamente conocen las categorías para las que fueron entrenados.

¿Qué sucede si necesitamos detectar objetos específicos que no forman parte de esas categorías?

En este desafío deberán desarrollar su **propio detector de objetos utilizando YOLOv8**, entrenándolo para reconocer categorías personalizadas.

Para conseguirlo, cada estudiante deberá seleccionar los objetos que desea reconocer, construir un conjunto de datos original, preparar las anotaciones, entrenar un modelo y comprobar su funcionamiento.

Pero el desafío no termina cuando el modelo consigue detectar los objetos. También deberán desarrollar una aplicación que utilice las detecciones para resolver un problema concreto, integrando el modelo entrenado con programación en Python.

> **El desafío.** Desarrollar un detector de objetos personalizado utilizando YOLOv8, entrenado con un dataset original construido por el estudiante. El modelo deberá reconocer y localizar **al menos dos categorías** de objetos seleccionadas previamente. Además, deberán integrar el detector en una aplicación funcional que utilice sus resultados para realizar una tarea concreta.

### Objetivo

Construir, entrenar y evaluar un modelo personalizado de detección de objetos mediante YOLOv8, integrándolo en una aplicación desarrollada en Python.
